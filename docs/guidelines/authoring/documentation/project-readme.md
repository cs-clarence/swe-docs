# Project README

## Scope

The entry document of a project, at the top of its repository or package. It orients the reader and sends them elsewhere. For documents it links to, see [choosing-a-type](choosing-a-type.md).

## Guidelines

### Say what it is and who it is for

Open with what the project does, who it serves, and what it does not do, in a few sentences, so a reader can decide to continue.

### Get to a first success quickly

Give the shortest path to a working result: install, run, and see something. Keep the steps few and verified ([make examples runnable](documentation.md#make-examples-runnable)); link to a [tutorial](tutorials.md) for more.

### Link instead of containing

Point to tutorials, guides, reference, and explanations for depth. A README that holds everything gets long and stale ([link to facts instead of copying them](documentation.md#link-to-facts-instead-of-copying-them)).

### Say how to get help and contribute

State where to ask questions or report problems, how to contribute, and the license. Link to [developer-docs](developer-docs.md) material for contributors.

### State status and support

Say how mature the project is and what is supported, such as versions and platforms.

## Exceptions

Internal tools may skip the license and contribution parts. A project with only one or two documents may hold them in the README.
