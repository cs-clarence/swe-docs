# Documentation

Writing documents for users and for developers. Part of [authoring](../README.md). Start with [choosing-a-type](choosing-a-type.md).

| File | Covers |
| --- | --- |
| [documentation](documentation.md) | Rules for every document. |
| [choosing-a-type](choosing-a-type.md) | Which type of document fits what the reader needs. |
| [tutorials](tutorials.md) | Teaching a newcomer by doing. |
| [how-to-guides](how-to-guides.md) | Helping a reader finish a task. |
| [reference](reference.md) | Describing facts for lookup. |
| [explanation](explanation.md) | Giving context, reasons, and trade-offs. |
| [project-readme](project-readme.md) | The entry point to a project. |
| [release-notes](release-notes.md) | Telling users what changed, deprecated, or broke. |
| [developer-docs](developer-docs.md) | Documents for people changing the code, kept with the code. |

User-facing types (tutorial, how-to guide, reference, explanation) follow the Diátaxis model. Developer-facing documents mostly live in the code; see [developer-docs](developer-docs.md).
