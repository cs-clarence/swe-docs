# How-to guides

## Scope

Documents that help a reader complete a specific task. For teaching newcomers, see [tutorials](tutorials.md).

## Guidelines

### Name the task as the reader's goal

Title the guide by what the reader wants to achieve, such as "Rotate an access key", not by the feature or tool used. Readers search by goal.

### Assume the reader knows the basics

Start from the task. Link to [tutorials](tutorials.md) or [explanation](explanation.md) for background instead of teaching it.

### Give ordered steps with one action each

Write steps in the order they are done, each as one action. Say how to check that the task worked at the end, and at any step that is easy to get wrong.

### Cover the task, not every option

Describe the common path. Link to [reference](reference.md) for options and to other guides for variations, so the steps stay short.

### Cover the likely failures

Where a step commonly fails, say how to recognize it and what to do. Keep it next to the step it concerns.

## Exceptions

Tasks with real alternatives, such as different platforms, may branch. Label each branch at the point it starts.
