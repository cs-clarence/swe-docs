# Reviewing

How to evaluate a change. Rules live in [authoring](../authoring/README.md); reviewing adds process and checks that link to them. Shared terms and tiers are in [core](../core/README.md). Plans can be reviewed before any code exists, using the [planning checks](checks/planning/plan-a-change.md), including [for agents](checks/planning/agents.md).

| File | Covers |
| --- | --- |
| [process](process.md) | Order, depth by risk, blocking versus optional, responsibilities. |
| [feedback](feedback.md) | Writing actionable comments. |
| [by-tier](by-tier.md) | Which checks to run at each risk tier. |
| [examples](examples.md) | Sample review comments. |
| [checks/](checks) | Yes/no checks per area, linked to the rules they verify. |
| [agents](agents.md) | Reviewing agent output, and agents as reviewers. |

Review against the *effective* rules. Apply the repository's [overrides](../core/precedence.md#overriding-rules) first.
